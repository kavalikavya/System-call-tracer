CONCEPT IN SIMPLE STEPS

How a System Call Works

Follow one request from start to finish
01

What is a system call?

A system call is the controlled interface used by a user program to request a service from the operating system kernel. Applications cannot directly perform privileged operations such as accessing hardware or protected files, so they ask the kernel to do it.

STEP 1

Application requests a service

A program calls a library/API function such as read(), write(), open() or fork().

Program → library/API
STEP 2

System-call entry

The system-call mechanism transfers control from user mode to kernel mode. The CPU uses a controlled entry point rather than allowing the application to enter the kernel arbitrarily.

User Mode → Kernel Mode
STEP 3

Kernel handles the request

The kernel identifies the requested service, checks arguments and permissions, and performs the required operation using privileged OS resources.

Dispatcher → Kernel Service
STEP 4

Result is returned

The kernel produces a return value or error. Control is transferred back to the application, which continues execution in user mode.

Kernel → User Mode

Why the operating system uses two privilege levels
USER MODE

Application

Normal programs run here with restricted privileges. They cannot directly access protected kernel resources.

printf() → write()
↕system-call entry / return
KERNEL MODE

Operating System

The kernel runs with higher privilege, validates requests and performs protected operations.

sys_write() → file/device

CLEAR THEORY

System Call Concept Guide

Definitions you can explain in a viva
System Call

A controlled mechanism through which a user program requests a service from the operating-system kernel.

Example: read() asks the OS to read data.
User Mode

A restricted CPU privilege level where ordinary applications execute. Direct access to protected resources is not allowed.

Think: application space
Kernel Mode

A privileged execution level used by the operating-system kernel to perform protected operations.

Think: OS control space
System-Call Interface

The boundary/API through which programs request operating-system services such as files, processes, memory and communication.

Program → OS request
Arguments

Input values supplied with a system call. They tell the kernel what resource or operation the program wants.

Example: file descriptor + buffer + size
Return Value

The result sent back by the kernel. It can indicate success, a quantity, an identifier or an error condition.

Example: read() may return bytes read
Trace

A chronological record of system calls made by a program, including call names, arguments and results.

Trace = execution evidence
Trap / Syscall Entry

A controlled CPU transition that transfers execution to a kernel entry point so the requested service can be handled safely.

User → Kernel boundary
30-SECOND EXPLANATION

How to explain this project

“Our project is a System Call Tracer and Visualizer. A system call is the interface through which a user program requests an operating-system service. Our tool records the calls made by a sample program and visualizes the transition from user mode to kernel mode and back. For every call, we show the syscall name, arguments, return value, status and execution order. This helps us understand how applications interact with the operating-system kernel.”

WORKED EXAMPLES

Understand System Calls Through Examples

See why common programs need the kernel
EXAMPLE 01

Printing “Hello World”

When a program prints text, it eventually needs an OS service to send bytes to the output device or terminal.

printf() → write() → kernel → terminal
EXAMPLE 02

Reading a file

A program cannot directly read protected storage. It requests the kernel to open the file and read its contents.

openat() → read() → close()
EXAMPLE 03

Network server

A server needs operating-system services to create a socket, bind it to an address, accept connections and exchange data.

socket() → bind() → listen() → accept()
EXAMPLE 04

Creating a child process

A program can start a child process and wait for it to finish before continuing.

clone() → wait4() → exit_group()
EXAMPLE 05

Creating a file

The program asks the kernel to create a file, write content, and release the file descriptor.

openat() → write() → close()
EXAMPLE 06

Deleting a file

A file name can be removed through a filesystem system call.

unlink() → write() → exit_group()
EXAMPLE 07

Listing a directory

The program opens a directory and requests its entry information from the kernel.

openat() → getdents64() → close()
EXAMPLE 08

Memory allocation

A process maps a memory region and later unmaps it when it is no longer needed.

mmap() → use memory → munmap()
EXAMPLE 09

Permission denied

An attempt to open a protected file fails, showing how system calls report errors.

openat() → error (-1) → write()
EXAMPLE 10

Inter-process communication

A pipe lets one process or execution path send bytes to another through read and write file descriptors.

pipe2() → write() → read() → close()
Important: the examples in this interface are educational sample traces. They demonstrate the expected system-call flow and presentation of the project; they are not a claim that the browser itself is tracing the host operating system.
