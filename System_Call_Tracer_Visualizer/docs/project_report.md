# 1. ABSTRACT

System calls provide the interface between user applications and the operating system kernel. Through system calls, applications request operating system services such as file access, process creation, memory management, and input/output operations.

The **System Call Tracer and Visualizer** is a web-based educational tool developed to trace and visualize system calls generated by sample programs. The system uses the Linux `strace` utility to capture system-call information and a Python Flask backend to process and analyze the trace data.

The application provides an interactive dashboard that displays system-call statistics, categories, execution duration, process information, parent-child process relationships, system-call timelines, return values, and user-mode to kernel-mode transitions.

The project aims to make Operating Systems concepts easier to understand by converting raw system-call trace information into an interactive visual representation.

# 2. INTRODUCTION

An Operating System acts as an interface between application programs and computer hardware. Applications cannot directly access many hardware and system resources. Instead, they request services from the operating system through **system calls**.

Examples of system calls include:

- Opening and reading files
- Creating processes
- Allocating memory
- Performing input/output operations
- Accessing system information
- Communicating with other processes

Linux provides several tools for observing system calls. One of the most widely used tools is `strace`, which records the system calls made by a program.

Although `strace` provides detailed information, its raw output can be difficult for beginners to interpret. The proposed project addresses this problem by providing a graphical web-based interface for analyzing and visualizing system-call activity.

# 3. PROBLEM STATEMENT

System calls are an important concept in Operating Systems, but students often find it difficult to understand their actual execution.

Traditional system-call tracing produces large amounts of command-line text containing system-call names, arguments, return values, timestamps, and execution durations.

The main problems are:

- Raw trace output is difficult to understand.
- System calls are not visually categorized.
- User-mode and kernel-mode transitions are difficult to observe.
- Process relationships are not easy to identify.
- Comparing different system-call events requires manual analysis.
- Beginners may find command-line tracing tools difficult to interpret.

Therefore, there is a need for an educational visualization tool that presents system-call information in a simple and interactive manner.

---

# 4. OBJECTIVES

The main objectives of the project are:

1. To trace system calls generated by sample programs.
2. To analyze system-call names, arguments, timestamps, return values, and execution duration.
3. To categorize system calls into meaningful groups.
4. To visualize the transition between user mode and kernel mode.
5. To display process IDs and process relationships.
6. To provide an interactive system-call timeline.
7. To allow filtering of system calls based on category.
8. To display system-call statistics through an interactive dashboard.
9. To help students understand practical Operating Systems concepts.
10. To provide a simple alternative to analyzing raw `strace` output.
